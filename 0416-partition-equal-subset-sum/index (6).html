LEETCODE 416

PARTITION EQUAL SUBSET SUM

Can you split one array into two perfectly balanced groups?

GROUP A SUM A = 0
GROUP B SUM B = 0

Understand the problem

Given an integer array, can you split it into two subsets whose sums are equal?

What is a subset?

Any selection of elements from the array. You pick each element independently.

Used at most once

Each element lands in exactly one group. Two equal values are still two different elements.

Every element goes into A or B, so A + B = total. If A = B, each is half of the total.

Build the intuition

“How can we know whether two equal-sum subsets exist?” Don't build both subsets. Shrink the question.

Original problem

Find two subsets with equal sums.

Transformed problem

Find one subset with sum = total / 2. The leftover elements automatically sum to total − total/2 = total/2.

Edge cases: odd total → false. Even total → target = total / 2. Target reachable → true, otherwise false.

Why Dynamic Programming?

For each number there are two choices: include it or exclude it. n numbers means 2ⁿ subsets, far too many to check one by one.

Green: path to target. Coral: overshoots or misses the target. Amber: a sum already seen at that depth (repeated work). Solid edge = include, dashed edge = exclude.

It's 0/1 Knapsack

Each element can be used once, we want an exact sum, and every element is either taken or skipped.

0/1 vs unbounded

With [2] and target 4: unbounded can reuse the 2 (reach 4). 0/1 can use it once (reach only 0 and 2). Our problem is 0/1.

Understand the DP state

dp[s] = True if sum s can be formed using the numbers processed so far.

nums = [1, 5, 11, 5], target = 11

dp[0] = True: sum 0 is always possible by selecting no elements. Everything else starts False because no positive sum has been formed yet.

dp[s] = dp[s] OR dp[s − num] (only when s ≥ num)

A sum is possible if it was already possible without this number, OR if s − num was possible and we add this number to that subset.

Why do we iterate backwards?

for num in nums:    for s in range(target, num - 1, -1):        dp[s] = dp[s] or dp[s - num]

Backwards, dp[s − num] still holds the state from before this number. Forwards, it may already include this number, so the same element gets used twice.

nums = [2], target = 4
Correct: backward

Incorrect: forward

Time complexity: O(n × target)


The outer loop handles n numbers. The inner loop checks up to target sums for each. Each check is constant work.




operations: 0 / 
Rows = numbers. Each row sweeps right to left (backwards). Each cell = one possible dp transition.


This is pseudo-polynomial time: the work depends on the numeric value of the target, not just how many numbers there are. Doubling the target's digits would square the work.


Growth comparison (log scale; target held fixed)






Space complexity: O(target)






One array is allocated, initialized, and then reused for every number. It is never copied per element.


2D DP


Reverse iteration is what makes this safe: row i only needs row i−1's values, and going right to left means those values are still untouched when we read them. Counts above are logical DP cells, not measured bytes.
