From counting possibilities to mastering Dynamic Programming.

Ways to make 5 with [1, 2, 5]

Understand the problem

You get coin values and a target amount. Return how many different combinations of coins add up to the amount.

Number of combinations

We count ways, not the fewest coins.

Unlimited supply

Each coin type can be used again and again.

Different denominations

Coins like 1, 2 and 5 are different types.

Order does not matter

2 + 1 and 1 + 2 are the same combination.

Impossible combinations

If nothing adds up exactly, the answer is 0 (not -1).

Can you understand the problem?

How should you think?

“If I need to make amount 5 using coins [1, 2, 5], how many different combinations are possible?”

Coin Change I (LeetCode 322)

Find the minimum number of coins.

For 5: answer 1 (just the 5). We compare options with min.

Coin Change II (LeetCode 518)

Find the number of unique combinations.

For 5: answer 4. We combine options with +.

Same combination, different order. [2, 1, 2] and [1, 2, 2] use one 1 and two 2s. They are one combination.

[2, 1, 2]: 212= {1, 2, 2}
[1, 2, 2]: 122= {1, 2, 2}

We need to count combinations without counting different arrangements of the same coins as separate answers. If we try every arrangement, one combination shows up many times.

Optimal substructure: ways to make 5 come from ways to make smaller amounts like 3 (add a 2) or 0 (add a 5).

Overlapping subproblems: the same smaller amounts are needed again and again.

Reuse: store each count once in an array. Here we count ways instead of minimizing cost.

Understand the DP state

“How many ways can I make amount a using the coins processed so far?” Store it as dp[a].

dp[0] = 1: there is exactly one way to make 0. Choose no coins. That single empty way is what every bigger count is built from. If dp[0] were 0, every count would stay 0 forever.

Other cells start at 0: so far no combinations are known for positive amounts.

Coin Change I
dp[0] = 0

0 coins are needed. The other cells start at infinity.

Coin Change II
dp[0] = 1

1 way to make 0. The other cells start at 0.

Derive the recurrence

dp[a] += dp[a - coin]

Only when a >= coin.

  1. Select a coin.
  2. Consider the current target amount a.
  3. Remove the coin from the target: a - coin.
  4. Look at how many combinations make the remaining amount.
  5. Add those combinations to dp[a].

Why add? Every way to make a - coin becomes a new way to make a by putting one more coin on it. Different sources give different combinations, so their counts add. min would throw ways away.

Coin 1

dp[a] += dp[a - 1]

Every way to make a-1, plus a 1.

Coin 2

dp[a] += dp[a - 2]

Every way to make a-2, plus a 2.

Coin 5

dp[a] += dp[a - 5]

Only for a ≥ 5. dp[5] += dp[0].

Why loop order matters

Correct: coins outside
for coin in coins:    for a in range(coin, amount + 1):        dp[a] += dp[a - coin]
Incorrect: amounts outside
for a in range(1, amount + 1):    for coin in coins:        dp[a] += dp[a - coin]

With coins outside, we finish all uses of coin 1 before coin 2 appears. Coins are always added in the same order, so 1 + 2 can exist but 2 + 1 cannot. With amounts outside, any coin can be the last one at every amount, so each ordering is counted.

Why the amount loop goes forward

Going forward, dp[a - coin] was already updated with this same coin, so the coin can be reused. Going backward, dp[a - coin] hasn't seen this coin yet, so each coin is used at most once.

Complexity analysis


Time: O(amount × coins)
The outer loop runs once per coin. The inner loop covers amounts from coin to amount. Each update is constant work.


Space: O(amount)
One array with amount + 1 entries. This is the one-dimensional optimized solution.

State

Transition
dp[a] += dp[a - coin]
