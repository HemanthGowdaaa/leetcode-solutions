Coin Change

From brute-force thinking to Dynamic Programming mastery.

Time: O(amount × coins)Space: O(amount)
11

Understand the problem

You get a list of coin values and a target amount. Return the fewest coins that add up exactly to the amount. If no combination works, return -1.

Minimum number of coins

Many combinations may work. We want the one that uses the fewest coins.

Unlimited supply

You can reuse any coin as many times as you like.

Different denominations

Each coin has its own value, like 1, 2 or 5.

Impossible combinations

With only 2-value coins you can never make 3, so the answer is -1.

Can you understand the problem?

For coins = [2, 4] and amount = 7, what is the answer?

How should you think?

Ask: “If I need to make 11 using [1, 2, 5], what should I do?” The last coin you add must be one of three choices.

1→ now make 10
2→ now make 9
5→ now make 6

Every choice leaves a smaller version of the same problem.

Why greedy can fail

Greedy always takes the biggest coin that fits. Try coins = [1, 3, 4], amount = 6.

Greedy

Optimal

Optimal substructure: the best answer for 11 is built from the best answers for smaller amounts like 10, 9 and 6.

Overlapping subproblems: amount 6 gets needed again and again through different paths. Solving it once and remembering the result is what Dynamic Programming does.

Build the DP intuition

Central question: what is the minimum number of coins needed to create amount a? We store the answer as dp[a].

dp[0] = 0: zero coins make amount zero. Every other cell starts at amount + 1 = 12 (shown as INF). No valid answer can need more than amount coins, because the smallest coin is at least 1. So 12 safely means “not reachable yet”.

dp[a] = min(dp[a], 1 + dp[a - coin])

Only when a - coin >= 0. Read it as steps:

    Complexity analysis
    

    Time: O(amount × coins)
    The outer loop runs amount times. For each amount the inner loop visits every coin. Each visit does constant work: one subtraction, one lookup, one min.
    

    Space: O(amount)
    We keep one array with amount + 1 entries. Nothing else grows with the input.

    Final recap
    

    Problem
    Fewest coins to make an amount.
    State
    dp[a] = fewest coins for amount a.
    Initialization
    dp[0] = 0, all others amount + 1.
    Transition
    dp[a] = min(1 + dp[a-c]) for all valid coins c
    

    Answer
    dp[amount], or -1 if it still equals amount + 1.
    Time: O(amount × coins.length). Space: O(amount).
    

    You don't master Dynamic Programming by memorizing solutions. You master it by understanding how smaller problems build bigger answers.
